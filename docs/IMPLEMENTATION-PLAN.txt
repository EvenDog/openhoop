# Native Mac Embroidery Digitizer — Revised Plan After Cross-Review

## Goal and scope
An offline Apple Silicon Mac application for personal manual digitizing of small logos and patches, with familiar digitizing tools in a native Mac layout. Import PNG/JPEG reference artwork and a defined editable SVG subset; draw and edit running, satin and tatami objects; preview sewing; save editable projects; import/export PES, DST, EXP, JEF, VP3, XXX and PEC. Brother PES is the primary physical test target. Include configurable single-key/modifier shortcuts and named dock/toolbar layouts in release one.
Typed lettering, auto-digitizing, editable EMB import, individual-stitch editing, fancy fills, caps, HUS/VIP, Windows, multi-step shortcuts, floating docks and custom themes are deferred. No implementation or dependency installation occurs during this plan review.

## Application, commands and customization
Use an AppKit application lifecycle with NSDocument and NSWindowController, hosting SwiftUI inspector/settings content. Use an AppKit/Core Graphics canvas, NSSplitViewController for left/center/right panes, and NSToolbar for configurable toolbar items. Keep geometry/generation in a testable Swift package; isolate pinned Clipper2 C++ clipping/offsetting behind a C ABI wrapper with explicit ownership. Do not use Clipper2 triangulation. Bundle a pinned pyembroidery helper with a pinned compatible Python/PyInstaller build using onedir inside the app. Retain these narrow reuse boundaries rather than writing seven codecs or changing GUI frameworks.

Every user-invoked tool/action uses a stable command registry: ID, title, category, applicable contexts, enabled state, default keys, repeat behavior, and handler. Include drawing, node editing, selection, transforms, sequencing, property-field focus, view toggles, playback, file operations and workspace controls. Continuous gestures are not discrete hotkeys. Standard Cut/Copy/Paste/Undo/Redo/Select All/Delete handlers dispatch through the native responder chain, reaching the field editor when it has focus and the document/canvas otherwise.

Shortcut settings have search by command/category/key, key recording, multiple alternate bindings, clear/reassign, explicit collision replacement or cancellation, per-command/all reset, named profiles, duplication, and versioned JSON import/export. Preserve unknown imported command IDs as inactive entries with a warning. Do not let new app defaults displace user overrides. Menus, toolbar tooltips and the settings catalog show current keys; the first binding is the menu display, alternatives appear in tooltips/catalog.

Store printable shortcuts as the base character under the active keyboard layout with Shift/Option/Control/Command removed, plus the explicit modifier set. Use named identities for nonprinting keys such as Escape, arrows and F-keys; do not use raw physical-key positions for printable keys. Only Shift, Control, Option and Command are stored as modifiers; discard Caps Lock, function and numericPad flags. Keypad digits deliberately share the main-row digit binding. Normalize record/match/conflict checks identically; rebuild mappings on layout changes and report unavailable/conflicting bindings rather than guessing. Explain that F-keys may require Fn based on macOS keyboard settings.

Contexts are application-wide, canvas-idle, canvas-digitizing, list-panel, field-editing, modal, and shortcut-recording. Object lists and palettes retain arrows, Delete and Return for their registered selection/list actions; disable native jump-to-row type selection and forward other unhandled tool keys to the document router. Tool-selection commands explicitly apply in list-panel context, so clicking a panel does not disable them. Conflict checks include list-panel bindings. Application-wide bindings overlap every eligible normal context; canvas-idle and canvas-digitizing are mutually exclusive; text/modal/recording suppress canvas actions. Recorders and dialogs receive events first. Native text editing/IME receives keys while a field is focused, except legitimate application-wide commands such as Save. Canvas keyDown/performKeyEquivalent routes drawing-specific commands before idle commands only when the canvas is the first responder. Canvas-only shortcuts, including plain letters and field-conflicting modified bindings, use an attributed menu-title shortcut suffix with an empty keyEquivalent; never set a live equivalent merely for display. Native app-wide menu shortcuts use one adapter from normalized binding to keyEquivalent and keyEquivalentModifierMask; disable AppKit automatic shortcut localization and mirroring because the app already resolves the layout. The Stage 1 spike verifies shifted punctuation and Option combinations through both dispatch paths before enabling those native equivalents. Dispatch each event once. Enter commits a valid property field and returns focus to that document's canvas; Escape cancels the field edit and returns focus; Tab retains normal field traversal. Validation errors retain field focus. Only nudging/zoom-like commands repeat on held keys.

Retain a central canvas. Panel move-left/move-right and reorder controls, resizing and visibility toggles provide dock rearrangement; native toolbar customization selects/reorders items. Drag-to-dock is deferred. Named workspace definitions are app-wide and applied to all document windows, with per-window sizes clamped to the available window. Persist toolbar items, panel order/side/visibility/widths, not document selection or zoom. Keep Settings and Restore Default Workspace reachable from the application menu. Profiles/layouts are versioned preferences separate from design files.

## Editor and document model
Canvas includes millimeter rulers, grid snapping, zoom/pan, user-configured rectangular or oval sewing area, dimensions and stitch count. PNG/JPEG reference images can be positioned, scaled, locked and given opacity. Manual tracing only. Editable objects support selection/multiselect, Bezier handles and corner/curve nodes, insertion/deletion, move/resize/rotate/mirror, duplicate/group/hide/lock, order and numeric dimensions. Visibility only changes display, not the sewing sequence. Running paths, paired-rail satin and closed fills with holes are first-class types. Left-click creates corners, right-click creates curve points; normalize trackpad secondary click and Control-click while suppressing contextual menus during drawing. Enter finishes, Backspace removes the last drawing point and Escape cancels; keyboard commands are configurable.

Use Foundation XMLParser for a scoped SVG importer: path commands including arcs, rect, circle, ellipse, line, polyline, polygon and g/svg grouping; viewBox, explicit units, nested transforms, direct and inline-style fill/stroke, and evenodd/nonzero fill rules. Resolve to editable paths. Report unsupported live text, use/symbol, external styles, masks, clips, gradients, filters and external resources; do not silently turn unsupported content into embroidery. Disable external-entity resolution. Imported geometry remains unstitched until a stitch type is assigned; no automatic satin reconstruction is promised.

NSDocument owns main-actor editable state. Background tasks receive immutable value snapshots with document revision, object IDs and object geometry/settings revisions. All edits register inverse operations with UndoManager; a drag or field editing session is one undo item. Cache per-object stitch results by geometry/settings/transform and engine version; recompute sequence connectors when order, color or endpoints change. Publish only results matching the current document revision. Between same-color objects with coincident endpoints (within 0.05 mm), continue sewing unless an explicit trim is requested. For other inter-object gaps, default to tie-off/trim/jump/tie-in; users can select an untrimmed jump for that connection. A color change is an explicit boundary with tie-off and tie-in. Do not introduce an implicit sewn travel line between objects. Compilation is cancellable and never blocks canvas navigation.

A .stitchproj document package stores versioned JSON, embedded artwork, geometry/settings, ordered objects/groups, thread IDs and colors, hoop dimensions, imported raw stitch blocks, engine version and the last successfully compiled stitch snapshot. Autosave uses NSDocument. On an engine-version mismatch, retain a preview-only cached snapshot and require an explicit regeneration review before geometric editing or any export; cached-snapshot export is deferred. Opening such a document does not mark it dirty or trigger an autosave rewrite. Unknown future schema versions open as an unsupported-version error without overwriting the file.

Imported embroidery remains raw stitch blocks: positioning, rotation, mirroring, recoloring and combination with geometry are supported. Scaling does not pretend to regenerate digitizing objects; show a density warning and validate resulting moves. Missing imported thread colors receive deterministic placeholders labelled unknown, which the user can replace. Preserve source control commands and report unsupported commands rather than silently discard them.

## Stitch engine decisions
Internal coordinates are Double millimeters, with origin at sewing-area center, X right and Y up. Apply object transforms before generation with stitch directions transformed consistently. Adaptive Bezier flattening tolerance starts at 0.05 mm. Quantize only at the export boundary. These are engineering defaults for stabilized woven-fabric test swatches, not claims about all materials/machines.

Running stitches follow arc length with default 2.5 mm length and mandatory corner preservation. Satin uses two editable rails plus ordered direction rungs; match equal normalized arc-length positions separately between successive rungs. Alternate rails along centerline progress. Reject crossing rails/rungs, reversed correspondence and zero-area spans with object-local diagnostics. Default row spacing is 0.4 mm between successive pairs and compensation is 0.2 mm per side. Warn on widths below 1 mm or above 7 mm; block spans above the configured maximum stitch length (10 mm initially) and advise separate columns or fill. Detect crowded inner edges; automatic advanced corner/short-stitch algorithms are deferred, so tight corners require reshaping or separate columns rather than a silent quality claim.

For v1, uniform polygon expansion is the only fill compensation: apply its offset once, then rotate the expanded polygons into scanline coordinates, clips evenly spaced rows with holes respected, and subdivides them into monotone sections when interval connectivity splits/merges. Sew each section in alternating row directions with staggered needle positions. Connect rows only through validated in-region boundary/short-segment routes. Use explicit tie-off/trim/jump/tie-in between sections or whenever no valid connector exists; optimized inter-section travel is deferred. Default row spacing is 0.4 mm and maximum top stitch length is 3 mm. Expose this as Fill Expansion, initially 0.2 mm (holes contract accordingly). There is no second directional pull-compensation pass for fills in v1; satin compensation remains separate. Entry/exit handles snap to valid traversal endpoints and display their actual positions.

Underlay options: satin center run (default), inset edge run and zigzag; fill inset edge run plus perpendicular sparse tatami (default). Initial edge inset is 0.4 mm, sparse/zigzag spacing 1.2 mm, and underlay run length 2.5 mm. Clip underlay to its intended inset region; report collapsed regions instead of emitting stray stitches. Keep underlay, compensation and ties configurable per object and visible in preview.

The Swift engine owns geometry, underlay, sewing order, ties, and semantic TRIM/STOP/COLOR_CHANGE/END events. A default 0.3 mm minimum-length cleanup removes only redundant sewing points when corner/shape tolerance and command boundaries remain valid; intentional locking stitches are explicitly tagged and separately checked. Do not impose an impossible universal minimum by deleting required corners or control events. Report unresolved short stitches. Subdivide ordinary overlength runs/fills; do not silently split overwide satin across the column. Validate all finite coordinates, actual compensated bounds and generated sewing moves.

Expose compile(snapshot) -> StitchPlan(commands, threads, bounds, per-object provenance, diagnostics). Preview outlines, actual sewing/jump paths, needle points, shaded threads, and color/stitch playback. Preserve user object order.

## Export ownership and compatibility
Swift owns user file access and atomic writes. A helper invocation exchanges bounded versioned JSON over stdin/stdout with structured errors, stderr diagnostics, cancellation and a timeout; it receives file bytes (base64) rather than arbitrary destination paths. Import returns raw StitchPlan data. prepareExport returns encoded bytes, a decoded machine-plan preview, command/color mapping information and diagnostics. Verify the decoded plan and save those exact prepared bytes for the matching document revision and export settings; do not encode again after preview.

Use the pinned library's writer normalization once in the Python adapter for target-format movement limits, command representation and rounding. Set tie_on=False and tie_off=False explicitly because Swift already owns ties. Pass PES version explicitly; default version 6, version 1 available for compatibility testing with older machines. Do not bypass all encoding indiscriminately, and do not normalize once for preview and a second time to write. The adapter converts mm/Y-up into pyembroidery's 0.1 mm/Y-down coordinates exactly once. After writing, decode the bytes, inverse-convert, validate bounds/needle penetrations/order within target precision, and show expected command transformations.

Freeze per-format mapping fixtures and advertised capabilities from the pinned writers. Explicit known expectations: standard DST has no native RGB thread palette and uses jump sequences for trim requests; report trim behavior as machine-dependent. EXP without a color companion gets unknown color placeholders on import. PES/PEC stop requests become a same-thread color change; show the added change. Show palette mapping for PES/PEC, JEF and XXX; preserve exact thread intent in the project and optional thread-sequence CSV. VP3 carries its thread information. Any requested behavior that cannot be represented or verified must produce an export diagnostic rather than being silently dropped or claimed hardware-compatible. User-configured sewing dimensions constrain the actual rounded machine plan; exceeding them blocks export and reports overflow amounts. Also inspect encoded hoop/header metadata instead of assuming that a successful library call faithfully represents arbitrary hoop dimensions.

The precise Brother model, controller behavior and hoop sizes remain missing test inputs, not invented machine capabilities. Capture them before physical acceptance and document the tested combination. Support the generic custom sewing area and both PES variants in the meantime. All seven formats must pass structural and mapping tests; only formats/controllers physically tested may be described as machine-verified.

## Delivery and acceptance
Stage 1: app/command skeleton, shortcut routing spike, workspace preference round-trip, image reference manual tracing, running stitches, document save/reopen, and packaged PES export. Package the onedir helper immediately; freeze compatible dependency versions after this smoke test. Use a local non-App-Sandbox build with ad-hoc signing of nested helper code first and the parent app last; App Store sandboxing and notarized distribution are deferred. Check arm64 binaries with lipo, inspect otool -L dependencies and bundled Python search paths for references outside the app (Apple system libraries are allowed), and run import/export in a disposable Mac test environment without separately installed Python. If that environment is unavailable, record isolation as unverified; Finder launch or PATH removal alone is insufficient proof. Export/reopen a known-size asymmetric running sample with two colors, trim and stop cases; check independent decoding and a small Brother sew-out before calling the end-to-end path proven. Collect model/hoop settings at this checkpoint. Do not count the same pyembroidery reader as independent evidence.
Stage 2: satin, tatami, underlay, fill/satin compensation, object editing/sequence/playback and save/recovery behavior. Do algorithm and physical test swatches before treating stitch quality as accepted.
Stage 3: scoped SVG import, all seven machine imports/exports, full named shortcut/workspace management, format mapping reports and final local packaging. The command registry and working customization are present in Stage 1; Stage 3 expands/completes them rather than retrofitting hardcoded tools.

Test matrix:
- Every registry entry has unique ID, defined context, runnable handler and binding round-trip tests. Real key-event UI tests cover canvas idle/digitizing, tool keys after object-list/palette selection, list navigation/delete priority, field typing, IME, standard edit commands, modal/recorder priority, Shift/Option punctuation, alternate layouts, Caps Lock, Fn/arrow event flags, keypad equivalence, held keys, native-menu translation and display-only menu annotations and no double dispatch.
- Switch layouts with multiple documents, resize windows, restore defaults, import malformed profiles, relaunch and recover missing panel/command IDs without losing access to Settings.
- Geometry fixtures: straight/curved paths, tapered satin, tight-corner diagnostics, holes and concave fills, tiny/collapsed regions, invalid rails/rings, underlay and compensated boundaries. Assert deterministic generation; clipped rows cover intended intervals once; sewn travel segments stay in the intended region; discontinuities are explicit jumps with the configured trim/tie semantics.
- Save/reopen and undo/redo preserve geometry and parameters; cached results match revisions; engine changes cannot silently modify saved sewing plans. Source vs exported-coordinate error at original needle points is at most 0.1 mm per axis; additional penetrations/control records must match the chosen format rules.
- Per-format fixtures verify actual encoded bytes/control semantics and decoded scale/orientation/colors, beyond round-trips through one library. Independent viewer/hardware results are recorded separately.
- On the current Mac, target at least 30 fps pan/zoom with 100,000 stitches and observable cancellation within 100 ms for the Swift engine; helper cancellation terminates that invocation. These are measured targets, not current claims.
- Final Brother swatch covers run/satin/fill with a hole, underlay, two colors, stop/trim handling, sizing and registration. Record material/thread/stabilizer/settings and fix defects before production-ready status. UI/source review cannot establish sew-out quality.
